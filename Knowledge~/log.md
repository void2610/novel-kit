* **Update**: 辞書ルビの適用を `NovelCommandHandler` に集約。従来は `IRubyDictionary` を DI で受けても「いつ ApplyTo するか」が game 側 View の裁量で、呼び忘れれば無言で効かず、呼ぶ位置を誤ると既読 ID/バックログにふりがなが混入した (CR が View 側適用にしていたのは混入回避の逃げ場)。既読 ID とバックログを確定した**後**に表示用テキストへだけ適用することで、裁量の排除と混入回避を両立。契約はテストで固定 (表示に付く / 既読 ID 不変 / バックログ不変 / 未供給ならそのまま / 早送り行も初出を消費 / 選択肢にも付く)。「初出のみ」の周回リセット (`ResetShown`) は game 所有のまま (runner が呼ぶとシナリオ単位リセットになりセマンティクスが壊れる)。二重適用の壊れ方 (noparse 内への markup 再注入で TMP タグがリテラル表示) を CHANGELOG の移行手順に明記。

* **Update**: セーブの JSON serde をライブラリが持つ形へ。[セーブ粒度](/design/decisions/save-snapshot.md) の当初帰結「ライブラリはセーブ形式を持たず game 所有」を改めるが、**永続化(保存する行為)は引き続き game 所有**で、novel-kit はセーブデータの表現までを渡す。主用途(標準): game は自前 JSON セーブ機構を持つ前提で、`Novel.Runtime` に公開クラス `NovelSaveData`(`[Serializable]`・プレーンフィールド・`From`/`ToSnapshot`・自前 serde でネスト可)と文字列版 `NovelSaveSerializer`(内部で `NovelSaveData` + Unity 標準 `UnityEngine.JsonUtility`・決定的出力・破損耐性)を追加。game はこれらで snapshot を自分の save に畳み込む。novel-kit の責務はデータ表現までで、**永続化(ファイル/PlayerPrefs への保存)はライブラリに持ち込まない**(「丸ごと任せる」内部完結モードは提供しない)。粒度/境界(永続は IStateStore の Capture・境界は PlayAsync の狭間)は不変。color-recollection のセーブ実装(フラグ/既読の game 側直列化)を参考にデータ表現をライブラリへ集約。EditMode `NovelSaveSerializerTests` 追加(Unity 未起動の本環境ではテスト未実行)。
* **Update**: `ISaveStore` を撤去し、snapshot 授受を runner が直接露出する形へ([セーブ粒度](/design/decisions/save-snapshot.md))。従来は runner が `PlayAsync` の開始/終了で `ISaveStore.Load/SaveAsync` を自動呼びしていたが、(1)再生フローに game の IO を差し込む (2)「毎シナリオ境界で保存」ポリシーの押し付け (3)進行/セーブは game 所有([フロー境界](/design/decisions/flow-boundary.md))なのに制御が逆転、という問題があった。`ISaveStore`/`NullSaveStore` を削除し `INovelScenarioRunner` に `CaptureState()`/`RestoreState(snapshot)` を追加。live state はセッション中 runner が保持し、game は continue で `RestoreState`、保存時に `CaptureState()`→自前 serde/save する(再生フローから IO が消える)。`NovelStateSnapshot` を独立ファイルへ分離。api-surface / state-model / architecture / open-questions / implementation-review の参照を追随。EditMode runner テストを Capture/Restore ベースへ更新(Unity 未起動の本環境ではテスト未実行)。
