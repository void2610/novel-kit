# 1. シナリオファイルの基本

## ファイルの置き場所と名前

- シナリオは **Ruby スクリプト（`.rb`）** として書く。文字コードは UTF-8。
- Unity プロジェクトの `Resources/Scenarios/` 配下に置く（例: `Assets/Game/Resources/Scenarios/chapter1.rb`）。
  置くだけで自動的に `.mrb`（バイトコード）へコンパイルされる。
- ファイル名（拡張子なし）がそのまま **シナリオキー** になる。ゲーム側は
  `PlayAsync("chapter1")` のようにこのキーで再生を指示する。
  どのキーがどこで呼ばれるかは、担当エンジニアと命名を決めておくこと。

> ゲームによっては Resources ではなく独自の読み込み経路（Addressables 等）を使っている場合がある。
> その場合の置き場所はプロジェクトの指示に従うこと。

## 1 シナリオ = 1 ファイル

novel-kit は「1 つのシナリオを最初から最後まで再生する」ことだけを担当する。
シナリオの切り替え（章移動・マップ帰還など）はゲーム側の仕事なので、
`.rb` の中から別の `.rb` へジャンプする命令はない。
分岐の結果は[フラグ](./03-branching.md)として残し、ゲーム側がそれを読んで次のシナリオを決める。

## 書き方のルール

シナリオは Ruby として解釈されるが、覚えることは少ない。

```ruby
# 「#」から行末まではコメント（メモ書き）。実行されない

chara :alice                 # 命令は基本「命令名 引数, 引数, ...」の形
alice "こんにちは。"           # セリフ本文はダブルクォートで囲む
wait 0.5                     # 数値はそのまま書く
portrait :alice, "smile"     # :alice のような「シンボル」と "alice" のような文字列はどちらでも良い

alice "スコアは #{val(:score)} 点。"   # "#{...}" で文中に値を埋め込める
```

- **1 行 1 命令** が基本。上から順に実行される。
- キャラ id やキー（`:alice` / `"alice"`）はシンボルでも文字列でもよい（内部で文字列に揃えられる）。
- セリフ内で `"` を使いたい場合は `\"` と書くか、`'…'`（シングルクォート）で囲む。
  ただしシングルクォート内では `#{...}` の埋め込みが効かない点に注意。
- `if` / `elsif` / `else` / `end`、`==`（等しい）、`!=`（等しくない）あたりが書ければ分岐は書ける
  （詳細は [3 章](./03-branching.md)）。

## 動作確認

- `.rb` を保存すると Unity がインポート時にコンパイルする。**文法エラーがあるとこの時点で
  Console にエラーが出る**ので、まず Console を確認する習慣をつける。
- メニュー **Novel > Validate Scenarios** で、全シナリオがコンパイルできているか一括検証できる。
  「バイトコード未生成」と出たファイルは文法エラーの可能性が高い。
- 実行時のエラー（存在しないキャラ指定など）は、開発ビルドではシナリオ名と行位置つきで
  Console に出力される。

## 命令が「効かない」とき

`portrait` / `bg` / `se` などの演出命令は、ゲーム側がその機能を実装（配線）して初めて動く。
未配線の命令を呼んでもエラーにはならず **何も起こらない**（開発中は一度だけ Console に警告が出る）。
「書いたのに動かない」ときは、まずその機能がプロジェクトに配線済みかエンジニアに確認すること。
