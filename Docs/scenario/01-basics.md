# 1. シナリオファイルの基本

## ファイルの置き場所と名前

- シナリオは **`.rb` という拡張子のテキストファイル** に書く。文字コードは UTF-8
  （普通のテキストエディタで開いて書ける）。
- Unity プロジェクトの `Resources/Scenarios/` フォルダに置く
  （例: `Assets/Game/Resources/Scenarios/chapter1.rb`）。置くだけでゲームが認識する。
- **ファイル名がそのままシナリオの呼び出し名になる**。`chapter1.rb` なら、ゲームは
  「chapter1 を再生して」という形でこのシナリオを呼び出す。
  ファイル名の付け方は担当エンジニアと相談して決めること。

> ゲームによっては置き場所が別に決められていることがある。その場合はプロジェクトの指示に従うこと。

## シナリオは「命令」を上から並べたもの

シナリオファイルの中身は、**1 行につき 1 つの指示** を上から順に並べた台本。
この 1 行 1 行の指示を、本ガイドでは **命令** と呼ぶ。

命令の形はどれも共通で、**行の頭に「何をするか」、続けてその内容** を書く。

```ruby
portrait :alice, "smile"
```

この行を分解すると:

| 部分 | 意味 |
|---|---|
| `portrait` | 何をするか =「立ち絵を表示する」 |
| `:alice` | だれの → alice の |
| `"smile"` | どの絵を → 「smile」を |

内容が 2 つ以上あるときは `,`（カンマ）で区切る。それだけ。
どんな命令があるかは 2〜5 章で順に紹介し、[6 章](./06-reference.md)に一覧表がある。

## 覚えておく書き方のルール

### メモ書き（コメント）

`#` から行末までは実行されない。指示や覚え書きを自由に書いてよい。

```ruby
# ここから回想シーン
bg "school_old"    # 校舎は旧デザインの方を使う
```

### 文章は `"` で囲む

セリフや地の文などの文章は `"…"` のように囲んで書く。

```ruby
alice "こんにちは。"
```

文章の中で `"` そのものを出したいときは、`"` の代わりに `'…'` で囲めばよい。

```ruby
narration '看板には "OPEN" と書かれていた。'
```

### 名前の書き方は 2 通りある（どちらでも同じ）

キャラや画像などの **名前** は、`:alice`（頭にコロン）と `"alice"`（引用符で囲む）の
どちらの書き方をしてもよい。意味は同じ。

```ruby
portrait :alice, "smile"      # どちらの書き方が混ざっていても問題ない
portrait "alice", "smile"     # 上と同じ意味
```

本ガイドではキャラ名は `:alice`、画像や音の名前は `"smile"` のスタイルで統一している。

### 数はそのまま書く

秒数などの数は囲まずそのまま書く。小数も使える。

```ruby
wait 1.5      # 1.5 秒待つ
```

### 文章の中に数を埋め込む

文章の中に `#{…}` を書くと、その部分が実際の値に置き換わって表示される。

```ruby
narration "所持金は #{val(:money)} G になった。"
```

（`val` はフラグの値を読む命令。[3 章](./03-branching.md)で説明する。）

## 1 シナリオ = 1 ファイル

novel-kit が担当するのは「1 つのシナリオを最初から最後まで再生する」ことだけ。
シナリオの最後の行まで進むと再生は終わり、その後どうするか（次の章へ進む、マップに戻る等）は
ゲーム側のプログラムが決める。そのため、**シナリオの中から別のシナリオへ飛ぶ書き方はない**。
「どの選択肢を選んだか」は[フラグ](./03-branching.md)として記録し、ゲーム側がそれを見て次を決める。

## 書いたシナリオの確認方法

- `.rb` を保存すると、Unity が自動で読み込んでチェックする。**書き間違い（文法エラー）が
  あるとこの時点で Unity の Console ウィンドウに赤いエラーが出る**。まず Console を見る癖をつける。
- Unity のメニュー **Novel > Validate Scenarios** を実行すると、全シナリオを一括チェックできる。
  「バイトコード未生成」と出たファイルはどこかに書き間違いがある。
- 実行中のエラー（登場宣言していないキャラに喋らせた等）は、開発中のビルドなら
  シナリオ名・場所つきで Console に表示される。

## 書いたのに何も起こらないとき

立ち絵・背景・効果音などの演出は、**ゲーム側にその機能が組み込まれて初めて動く**。
まだ組み込まれていない機能の命令を書いてもエラーにはならず、**何も起こらない**
（開発中は Console に一度だけ警告が出る）。
「書いたのに動かない」ときは、書き間違いを疑う前に、その機能が使える状態かエンジニアに確認すること。
