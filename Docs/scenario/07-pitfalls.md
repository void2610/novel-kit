# 7. 注意点とよくある質問

## `n = …` の覚え書きは、間を空けて使わない

`n = choose(...)` のようにその場で付けた名前は、**選択肢の直後で使う分には問題ない** が、
あいだにセリフや演出をたくさん挟むと消えていることがある（シナリオを 1 行ずつ
再生する仕組み上の制約）。

後で使う結果は、必ずフラグに残す（[3 章](./03-branching.md)に安全な書き方の例がある）。

```ruby
# ◯ 直後に使う           # ◯ 後で使うならフラグに記録
n = choose(["A", "B"])    choose(["A", "B"], key: :picked)
if n == 0                 # …長い演出…
  ...                     if val(:picked) == 0
end                         ...
                          end
```

## `chara` の宣言を忘れるとエラーになる

```ruby
alice "こんにちは。"    # ✕ 先に chara :alice を書いていないと再生時にエラー
```

キャラ名でセリフを書くには、そのシナリオファイルの最初の方で `chara :alice` と
宣言しておくこと。エラーメッセージには undefined method（そんな言葉は知らない）と出る。

## 退場は `exit` ではなく `exit_chara`

`exit` は別の意味（プログラム全体の終了）に予約されている言葉なので、
キャラの退場には使えない。必ず `exit_chara :bob` と書く。

## フラグに入るのは整数だけ

フラグの箱に入れられるのは 0, 1, 2, … のような整数だけ。
文章や小数（0.5 など）は入れられない。文章を出し分けたいときは番号で分岐する:

```ruby
flag :heroine, 1
# ...
case val(:heroine)
when 1 then alice "私を選んでくれたのね。"
when 2 then bob "俺かよ。"
end
```

## `__` で始まる名前は使わない

フラグや選択肢の記録名に `__`（アンダースコア 2 つ）で始まる名前を付けない。
システムの作業用として扱われ、**セーブに残らない**。

## 名前の書き間違いは再生を止めない（が、警告は出る）

立ち絵・背景・音などの名前を書き間違えても、再生はそのまま続き「何も表示されない」だけになる。
ただし画像の名前が引けなかったときは Unity の Console に警告が出るので、
**立ち絵や背景が出ないときはまず Console を見ること**。

```
[Novel] シナリオ 'chapter1': 画像キー 'aria/smile' を解決できなかったため、その表示は空になります。
```

対応する機能がゲームに組み込まれていない場合も何も起こらないが、これも別の警告が出る
（[1 章](./01-basics.md)参照）。音の名前は仕組み上ゲーム側でしか判定できないため、警告は出ない。

Unity のメニュー **Novel > Validate Scenarios** を実行すると、存在しない名前を使っている行を
一括で警告してくれるので、まずこれを流す。そのうえで、
**書いた演出が全部出ているか、必ず実際に再生して通しで確認する**こと。

## シナリオの名前を間違えると「何も起きずに終わる」

再生するシナリオ自体の名前を間違えると、1 行も再生されないまま終わる。これも Console に警告が出る。

```
[Novel] シナリオ 'chpater1': バイトコードを取得できなかったため、何も再生せずに終了しました。
```

## 実行中にエラーが起きたときの読み方

`.rb` の途中でエラーが起きると、そこで再生が止まり Console に赤いエラーが出る。

```
[Novel] シナリオ 'chapter1' の 3 番目のセリフまで進んだ時点でエラー: undefined method 'portrai' (NoMethodError)
```

**行番号は出ない**（仕組み上の制約）。代わりに「何番目のセリフまで進んだか」が出るので、
`.rb` を上から数えてそのセリフを探し、その少し後ろを疑うとよい。

## セリフ中の変数は `#{}` ではなく `%{}` で書く

フラグや変数の値を文中に出すときは **`%{変数名}`** を使う。値は表示の直前に差し込まれる。

```ruby
flag :gold, 500
narration "所持金は%{gold}Gだ"     # → 所持金は500Gだ
```

`#{val(:gold)}`（Ruby の埋め込み）でも一見同じ表示になるが、こちらは**値が文面に焼き込まれる**ため
2 つの問題が起きる: ①多言語対応で翻訳テーブルと突き合わせられず翻訳されない
②値が変わるたび「別のセリフ」扱いになり既読スキップが効かない。`%{}` はどちらも起きない。

```ruby
# ✕ 焼き込み (翻訳不可・既読が割れる)    # ◯ 表示時に差し込む
narration "所持金は#{val(:gold)}Gだ"    narration "所持金は%{gold}Gだ"
```

- 使えるのは `flag` で設定した値（と、ゲーム側が用意した特別な変数。例: 主人公名。あるかは開発者に確認）
- 変数名は英数字とアンダースコアのみ。未定義の変数は `%{名前}` のまま表示される（＝書き間違いに気付ける）
- `%{` をそのまま表示したい場合だけ `%%{` と書く（ふつうの `%` はそのままでよい）

## Ruby に詳しい人向けの補足

シナリオの実行環境は mruby（の C# 実装 MRubyCS）で、通常の Ruby と一部挙動が異なる。
普通にシナリオを書く分には出会わないが、凝った書き方をする場合の注意:

- 実行時の `eval` は使えない。
- `method_missing` は使えない（`chara` が `define_method` で実メソッドを定義する方式なのはこのため）。
- `&:to_f` のような Symbol#to_proc 省略記法は使えない。明示ブロック `{ |x| x.to_f }` を使う。
- ローカル変数は命令（内部的には Fiber の中断・再開）を跨ぐと失われることがある。
  冒頭の「`n = …` は間を空けて使わない」の正体はこれ。

全シナリオ共通の自作ヘルパーを追加したい場合は、エンジニアに依頼して
追加プリアンブル（共通定義ファイル）として組み込んでもらう。

## よくある質問

**Q. セリフの途中で改行したい**
A. 改行したい位置に `\n` と書く: `alice "一行目\n二行目"`（[2 章](./02-text.md)参照）

**Q. 別のシナリオファイルへ飛びたい**
A. できない作り。フラグを残してシナリオを終え、次にどれを再生するかはゲーム側が決める（[1 章](./01-basics.md)参照）。

**Q. 書き間違い（文法エラー)の見つけ方は**
A. `.rb` を保存したとき Unity の Console に赤いエラーが出る。メニュー **Novel > Validate Scenarios** で全ファイル一括チェックもできる。

**Q. 既読スキップ・オート再生のために書くことは**
A. なし。既読の管理やオート/スキップは自動で処理される。

**Q. 使える立ち絵・背景・音の名前や構図の一覧は**
A. Unity のメニュー **Novel > Project Reference** に一覧が出る（キャラ・画像・構図・BGM/SE）。
Unity を開けない環境で書いている場合は、この画面の内容をエンジニアに共有してもらう。
